# Light/Dark 구현 기준

이 문서는 사용자가 승인한 두 시안의 시각적 방향을 구현자가 재현하기 위한 기준이다. 제품 요구사항은 해당 이슈와 기존 모듈 책임을 따른다. `reference.html`은 양쪽 모듈의 고정 예시 데이터를 사용하는 독립 참고 화면이며 실제 지도/예약 동작은 없다.

## 공통 구성

- 라이트: #f5f7fa 캔버스, 흰 패널, #172b4d 본문/헤더, #0f766e 주요 버튼. 다크: #0b1220 캔버스, #111c2e 패널, #17263c 상승 표면, #e6edf7 본문, #2dd4bf 강조선. 실제 값은 themes.json/tokens.css를 따른다.
- 헤더 56px, 브랜드 왼쪽·업무 내비게이션·오른쪽 테마/사용자 도구의 위계를 공유한다. 존재하지 않는 경로나 계정/인증을 참조 이미지 때문에 새로 만들지 않는다.
- 16px 본문·14px 보조·24px 화면 제목, 4/8/12/16/24/32px 간격, 6px 컨트롤·8px 패널 모서리, 44px 기본 터치 높이를 공유한다. 고밀도 지도 컨트롤도 실제 터치 영역은 유지한다.
- 주요 버튼은 청록 채움/흰 글자, 보조는 표면/control-border, 위험 버튼은 danger/on-danger다. 선택한 목록은 primary-subtle/on-primary-subtle과 accent 선으로 표시한다. 경고는 warning-subtle/warning 조합이다. 색만으로 상태를 전달하지 않는다.
- muted-border는 구획 장식용이다. 입력/포커스/선택 상태의 유일한 식별에는 control-border/focus/accent를 사용한다. hover/active/disabled/loading/error를 양 모드에서 확인한다.
- 로컬 Pretendard 또는 시스템 한글 sans 사용. 랜덤한 세리프/모노스페이스 제목·마케팅 hero·장식 gradient·카드 남발은 추가하지 않는다. 문구는 짧고 구체적인 한국어다.

## 지도 모듈

- 데스크톱은 약 300–340px 시설 목록/검색 패널과 남은 지도 작업 공간을 사용한다. 헤더 아래 지도 영역을 최대한 유지하며 조작 버튼·상세 카드는 지도를 가리지 않는 곳에 둔다.
- 검색·분류 칩·결과 수·선택 행을 한 묶음으로 배치한다. 지도는 선택 시설과 저장된 경계를 같은 accent 계열로 표시하고 기존 데이터 제공 경계와 구별한다.
- 모바일은 목록을 접거나 drawer/bottom sheet로 전환하고 지도 이동·측정·경계 편집의 조작 영역을 보존한다. 기존 접근성 대안을 유지한다.
- 실제 위성/DEM/래스터 지도는 데이터를 그대로 보존한다. 참고 화면의 어두운 벡터 지도는 가능한 데이터 표현의 예시다. 런타임에서 지원하지 않는 지도 스타일을 구현했다고 표현하지 않는다. 지도 전체에 CSS invert/brightness 필터를 적용하지 않는다.

## 예약 모듈과 통합 포털

- 같은 헤더/내비게이션/폼 컨트롤/테마 토큰을 사용한다. 예약 기능이 승인되면 시설·날짜 필터 → 주요 일정 영역 → 선택 정보/작업 영역 순으로 배치한다.
- 달력 날짜, 승인/확정 상태, 이용자 이름 등 참고 값은 디자인 fixture다. 실제 정책·기술 스택은 승인된 이슈/결정표에 따른다.
- 상위 포털은 업무 내비게이션과 공통 화면 위계를 제공한다. 아직 없는 인증·예약 화면을 설치 작업에서 새로 구현하지 않는다.

## 테마 선택 계약

- 표현값은 light / dark / system. html `data-theme="light"`, `data-theme="dark"`가 명시적 사용자 선택이고, system은 속성을 제거하여 CSS `prefers-color-scheme`을 따른다. OS 설정 변경은 system에서만 즉시 반영한다.
- 구현 시 `platform.theme`에 선택을 보관할 수 있다. localStorage 접근 실패나 잘못된 값은 system으로 처리하고 예외로 화면을 깨뜨리지 않는다. 서버는 브라우저 환경을 가정하지 않는다.
- 같은 origin에서는 탭 간 선택을 동기화할 수 있다. 서로 다른 모듈 origin의 localStorage가 자동 공유된다고 가정하지 않는다. 서버 사용자 설정 API를 새로 도입하는 것은 별도 업무다.
- 초기 표시/SSR/하이드레이션에 맞는 프로젝트 지원 방식으로 적용하고 테마 선택 때문에 입력·검색·선택 시설·지도 위치·경계 편집 상태가 초기화되지 않게 한다.
- 이 파일은 향후 UI 구현 규칙이다. 스킬 설치만으로 실제 앱의 전환 기능이 만들어지는 것은 아니다.

## 검증

자동: 파일 해시·세 저장소 동일성, 스킬 참조, JSON/CSS 재생성 일치, light/dark 동일 토큰 집합, 주요 텍스트/버튼/포커스 명암비와 실제 로컬 UX 검색을 검사한다.

UI 구현 완료 시: light/dark × 데스크톱 1440×900/모바일 390×844 스크린샷, 테마 전환·OS 변경·새로고침·저장 불가·키보드·기능 회귀 결과를 남긴다. 참고 HTML/스킬 검사와 앱의 실제 구현 검증을 구분한다.

참고 화면 실행: 저장소 루트에서 `python3 -m http.server 8874 --bind 127.0.0.1 --directory design-system/platform`으로 내부 검증용 서버를 시작하고 `/reference.html`을 연다. 관리형 브라우저가 file URL을 차단하면 이 로컬 HTTP 방식을 사용한다. 종료는 서버 터미널 Ctrl+C다.
