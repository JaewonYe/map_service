# 시험시설 플랫폼 공통 UI 기준

버전: 2.0.0. 기준 저장소는 JaewonYe/platform_core이며 각 모듈에는 동일한 스냅샷을 둔다. 사용자의 디자인 스킬 공통 적용 요청에 따른 초기 작업 기준이다. 기존 화면에 일괄 CSS를 주입하거나 예약 기능·기술 스택을 확정하는 변경은 아니다.

## 방향

시험시설 운영자가 지도·시설·예약 업무를 명확하게 처리하도록 사용자가 시각화로 확인한 light/dark의 남색·청록 시각 체계를 사용한다. 모듈마다 다른 테마를 생성하지 않는다. 지도는 작업 공간을 넓게 유지하고 예약 화면은 해당 기능이 승인된 뒤 같은 문법으로 구성한다. 시안의 일정·예약 상태는 업무 정책이 아니다.

## 색상·글꼴·간격

- 색상의 원본은 themes.json이며 tokens.css는 이 원본에서 생성한다. 색상을 컴포넌트마다 새로 만들지 않는다. 카드/배경/구조용 옅은 경계와 입력창/포커스 식별용 경계를 구분한다.
- 본문 글꼴은 로컬 Pretendard가 있으면 활용하고 없으면 시스템 한글 sans-serif를 사용한다. 스킬의 Google Fonts/CDN 예시는 자동 도입하지 않는다. 오프라인 지도의 외부 요청 제한을 유지한다.
- 본문 16px/행간 1.5, 보조 14px, 제목 20/24px를 기본으로 한다. 긴 한글·시설명·오류를 잘리지 않게 처리한다.
- 간격은 4/8/12/16/24/32px, 모서리는 컨트롤 6px·패널 8px다. 기본 조작 높이는 44px이며 모바일 터치 영역을 확보한다.

## 컴포넌트와 상태

- 주요 동작은 청록 채움 버튼, 보조는 흰 배경+식별 가능한 경계, 삭제는 위험 색상과 확인 흐름을 사용한다. 실제 동작을 설명하는 한국어 이름을 붙인다.
- 버튼·입력·분류 필터·목록 선택·상세 패널·대화상자의 hover/focus/active/disabled/loading/error 문법을 공유한다. 상태는 색만으로 표현하지 않는다.
- 공통 헤더와 내비게이션의 글꼴·높이·선택 표현은 일관되게 하되 지도 패널과 예약 달력처럼 업무별 배치는 허용한다. 승인되지 않은 메뉴/기능을 실동작처럼 추가하지 않는다.
- 로딩·실제 데이터 없음·검색 결과 없음·조회 실패를 구분하고 다음 행동을 제공한다. 저장 오류나 충돌은 입력을 보존한다.

## 접근성과 지도

- 일반 텍스트 명암비 4.5:1 이상, 큰 텍스트와 주요 비텍스트 요소 3:1 이상을 검토한다. tokens.css의 muted-border는 장식용이며 입력 식별이나 유일한 상태 표시로 사용하지 않는다.
- 키보드 접근, 보이는 focus, 실제 label, 아이콘 접근 가능한 이름, 대화상자 포커스 복귀를 확인한다. 모션 감소 설정을 존중한다.
- 지도 pan/zoom과 드로잉 조작을 전역 CSS로 막지 않는다. 터치/드래그만 가능한 필수 조작에는 버튼·키보드 대안을 제공한다. 모바일 safe area와 작은 화면에서도 지도 작업 공간을 확보한다.
- 실제 UI 변경은 데스크톱/모바일 스크린샷과 기능 회귀로 확인한다. 본 설치만으로 시각 검토나 접근성 인증이 완료된 것은 아니다.

## 스킬 사용 순서

1. 현재 저장소 AGENTS.md와 이 MASTER.md 및 tokens.css를 읽는다. 기존 UI 구현과 명시된 사용자 요구가 우선이다.
2. 프로젝트 전용 `.agents/skills/platform-ui-design/SKILL.md`와 [시안 구현 규칙](IMPLEMENTATION.md)을 먼저 읽는다. 이어서 `.agents/skills/ui-ux-pro-max/SKILL.md`를 읽고 Python 3 로컬 검색으로 필요한 권고를 확인한다. 기존 공통 기준을 다시 생성하거나 덮어쓰지 않는다.
3. 프로젝트 스택에 맞춰 구현한다. 지도는 기존 Next.js/Leaflet/CSS를 유지하고 예약은 승인된 구현 범위/기술만 따른다. 설치가 Tailwind·아이콘 패키지·외부 폰트·새 프레임워크 도입의 승인이 아니다.
4. `.agents/skills/web-design-guidelines/SKILL.md`와 번들 `references/command.md`로 변경한 UI를 검토하고 파일:줄 단위로 결과를 기록한다. 한국어에 부적절한 영문 대문자 표기·& 축약 규칙을 기계적으로 적용하지 않는다.
5. 결과는 디자인 검토, 기능 테스트, 원격 CI로 구분하고 실행·미실행을 보고한다. 스킬의 지침은 API·데이터 책임·사용자 승인 규칙을 변경하지 않는다.

## 유지관리

각 저장소의 `.agents/skills`와 이 기준 파일은 독립 체크아웃에서 동작한다. 상위 저장소는 원본/고정 버전과 공통 기준의 기준점이며 모듈에서 기준을 독자 수정하지 않는다. 변경은 상위에서 검토한 뒤 세 저장소에 같은 파일과 lock을 반영한다.

`python3 scripts/check_design_skills.py`로 로컬 파일 무결성과 실제 검색 동작을 확인한다. 상위에서는 `python3 scripts/check_design_skills.py --modules`로 초기화된 두 모듈의 스냅샷 일치도 확인한다. upstream 갱신은 새 커밋/라이선스/차이를 검토하고 lock과 모듈을 함께 갱신한다. 자동 최신 추적이나 강제 덮어쓰기는 하지 않는다.

새 Codex 작업에서 스킬 목록을 다시 읽는다. 현재 세션의 동적 스킬 목록에 즉시 노출되지 않으면 AGENTS.md의 명시적 SKILL.md 경로를 읽어 같은 절차를 사용할 수 있다. 설치 경로는 Codex용 `.agents/skills`다.
